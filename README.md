# Reported delivery records of clean energy infrastructure portfolios

Code, configuration and analysis outputs for the article

> *Predictable completion and weakly predictable attrition in multistate delivery records of
> clean energy infrastructure portfolios.* Smart and Sustainable Built Environment.

The study links the 129 monthly files of the United States Energy Information Administration
preliminary monthly generator inventory (Form EIA-860M, September 2015 to May 2026) into
delivery histories of 7,172 utility-scale clean energy generating units, represents them as a
nine-state delivery process, and evaluates fourteen model specifications for three outcomes:
the next reported state, operation within 12 months and cancellation within 24 months of first
report.

Version: the commit that adds this README (October 2026) holds the code and outputs of the
reported analysis.

Raw EIA files are public and are not redistributed. The annual EIA-860 archives listed in the
manifest were downloaded but are not used by the reported analysis; terminal outcomes come from
the May 2026 monthly inventory.

## Environment

Python 3.13 on Windows 11 was used for the reported run. Install the pinned dependencies with

```
python -m pip install -r requirements.txt
```

CatBoost, XGBoost, TabM and the purpose-built neural networks were run on a CUDA GPU (Quadro
T1000, 4 GB); LightGBM and all other learners run on the CPU. The exact versions and hardware of
the reported run are recorded in `outputs/delivery_twin/results/run_manifest.json`. Neural and
GPU results can vary slightly across hardware and driver versions; the logistic, tree and
descriptive results are deterministic for the fixed seed.

## Reproducing the analysis

1. Download the source files (about 1.3 GB):
   `python scripts/download_eia.py --manifest data/raw/download_manifest.csv --raw-dir data/raw`
2. Run the primary analysis (seed 20260713, 500 cluster bootstrap resamples):
   `python run_pipeline.py --raw-dir data/raw --output-dir outputs/delivery_twin`
   Outputs: `processed/` (unit histories, panel, transitions, landmarks), `tables/`
   (descriptive, model, calibration, decision-curve and bootstrap tables), `predictions/` (test
   predictions), `models/` and `results/` (run manifest, data-quality audit, validation checks).
3. Run the supplementary analyses (CPU, about two minutes):
   `python supplementary_analyses/run_supplementary.py`
   `python supplementary_analyses/next_state_cutoff.py`
   `python supplementary_analyses/contingency_backtest.py`
   Outputs are written to `outputs/supplementary/` (seed 20261016).
4. Regenerate the figures, written to `outputs/figures/`: `python figures/main_figures.py`
   (Figures 1 to 5), `python figures/make_supp_figures.py` (Supplementary Figure S1),
   `python figures/supp_figure_s2.py` (Supplementary Figure S2) and
   `python figures/supp_figure_s3.py` (Supplementary Figure S3)
5. Run the tests: `python -m pytest -q`

## Scope and interpretation

EIA-860M is a preliminary administrative inventory, not a contractual project-control system.
Results describe reported generating-unit trajectories; they are not causal effects, contractor
performance or a census of unreported early-stage projects. The purpose-built networks were
specified after the benchmark test results had been inspected, so their comparisons are
exploratory.
